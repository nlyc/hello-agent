### 2.3 指标

- 工具调用：AST 匹配（函数名精确 + 参数无序 + 值语义等价），按类别准确率。
- QA：准精确匹配（数字/字符串/列表归一化）、包含匹配、引用覆盖率。
- 质量：程序化约束（天数/预算/必含/避开）+ LLM Judge 四维（1–5）+ Win Rate（交换 A/B）。
- 效率：上下文 tokens、packets、LLM 调用、端到端耗时。

### 3.3 S1：ContextBuilder 上下文效率（离线）

命令：

```powershell

```

| 方案 | tokens | 说明 |
|---|---:|---|
| 朴素拼接 | 504 | 角色 + 输出 + 问题 + 资料 + 笔记 + **20 轮历史全量** |

其他观测：

- 6 个分区全部出现：role / task / state / evidence / context / output。
- 选中 13 个信息包，相关性过滤 0、预算丢弃 0。
- 跨会话：新建 `NoteStore` 仍能读到 blocker「故宫周一闭馆」。
- 小语料下结构化有固定标题开销；语料越小，tokens 节省越不明显；**长历史场景收益最大**。

## 4. 消融分析

| 变化 | 预期影响 | 当前证据 |
|---|---|---|
| 去掉 ContextBuilder | 历史全量、token 上升 | Demo：504 vs 260 |
| 去掉 NoteTool | blocker/action 需每轮重说 | 跨会话读取 blocker 已验证 |
| 去掉 TerminalTool | 攻略需预索引，更新后易过期 | JIT `grep` 已验证 |
| 去掉 MCP | 每个服务重复封装 Tool | 3 工具一次展开已验证 |
| 去掉 A2A | 多 Agent 只能进程内手写编排 | 3 Agent 远程链路已验证 |

S2–S5 的 **数值型消融**（工具准确率、QA QEM、Judge 分数）需要在线模型，待 M9.8 在线补跑。

## 5. 错误分析

| 现象 | 原因 | 处理 |
|---|---|---|
| 负基线工具调用 0 分 | `NoToolAgent` 从不调用工具 | 预期；用于验证指标 |
| QA 全 0 | 固定拒答 | 预期 |
| 行程质量仅 1/6 | 最小行程缺预算/同行人/路线约束 | 预期；程序化检查生效 |
| 上下文 Demo 中资料与笔记重复 | Evidence 与 blocker 来自不同层 | 真实场景可接受；P1 可按内容哈希去重 |
| 小语料 token 节省为负（首次运行） | 六分区标题固定开销 | Demo 改为 20 轮历史对照后 +48% |

## 6. 结论与选型建议

1. **ContextBuilder 在长历史/多来源场景收益明确**：本 Demo 节省 48%，且 blocker 不被淹没。
2. **NoteTool 适合跨会话项目记忆**：blocker/action 的结构化优先级比纯向量召回更稳。
3. **TerminalTool 适合探索式任务**：攻略、日志、代码库不必全部预索引。
4. **MCP 适合复用外部工具**：一次 server 封装，多客户端可用；工具描述仍是选择质量的关键。
5. **A2A 适合跨进程/跨团队协作**：任务生命周期与工件让链路可观测；代价是网络与序列化开销。
6. **评估必须先客观后主观**：AST/QEM/程序化约束先行，LLM Judge 只做补充。

---

## 7. 威胁与局限

- **在线对比未执行**：没有 `LLM_API_KEY` 时不伪造 S2–S5 分数；报告明确标注。
- **样本规模小**：12 + 9 + 6，适合工程回归，不足以做统计显著性结论。
- **LLM Judge 偏差**：长度偏好、位置偏好、自我偏好；已用顺序交换与 rubric 锚定缓解。
- **单一模型/单一领域**：结论主要适用于旅行助手与中文语料。
- **ReAct 文本协议**：parallel 类别按“调用集合覆盖”计分，不公平；P1 建议加 `FunctionCallAgent`。
- **离线 Embedder**：Hashing 模式语义弱于 FastEmbed；S0 数字来自 M8 的同一口径。
